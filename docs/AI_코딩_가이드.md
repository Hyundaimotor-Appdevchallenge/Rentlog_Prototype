# Claude Code · Codex로 개발할 때

AI 코딩 도구는 이 프로젝트의 **에뮬레이터 제약**과 **Pleos SDK 특성**을 모릅니다. 아래를 지키게 하면 시행착오가 크게 줄어듭니다. 루트의 `CLAUDE.md`(Claude Code)와 `AGENTS.md`(Codex)가 이 문서를 가리킵니다.

## 시작할 때
1. 세션 시작 직후 `README.md`, `docs/인수인계.md`, `docs/개발_가이드.md`를 읽게 합니다.
2. 작업 범위를 한 가지 목적으로 좁혀서 요청합니다. (예: "F-06 문구 수정", "문 열림 판정에 창문 추가")
3. 큰 작업은 먼저 계획을 세우게 하고(Claude Code의 plan 모드) 계획을 확인한 뒤 진행시킵니다.

## 반드시 지키게 할 규칙
| 규칙 | 이유 |
|---|---|
| 변경 후 `./gradlew assembleDebug testDebugUnitTest`로 검증 | 단위 테스트가 흐름 명세 역할을 함 |
| 화면·차량 로직을 바꿨으면 E2E도 실행: `python3 scripts/e2e_test.py --only <시나리오>` | 단위 테스트가 못 잡는 실제 화면 동작 확인 |
| Pleos SDK API 이름·값을 **추측하지 말고** 기존 래퍼와 SDK 문서에서 확인 | 존재하지 않는 API를 만들어 내는 경우가 많음 |
| SDK 호출은 항상 예외로 보호하고 시뮬레이터 폴백을 유지 | 일반 에뮬레이터에서 앱이 죽으면 안 됨 |
| `scripts/out/`, `build/`, `local.properties`, `.idea` 개인 설정은 커밋하지 않음 | 용량과 개인정보 |
| 비밀값·토큰·개인 경로를 코드, 문서, 커밋 메시지에 쓰지 않음 | **공개 저장소** |
| 테스트를 통과시키려고 테스트나 기대값을 임의로 바꾸지 않음 | 요구사항이 바뀐 경우에만 사람이 확인하고 수정 |
| 요청하지 않은 리팩터링·파일 이동 금지 | PR을 작게 유지 |

## 에뮬레이터를 쓰는 작업에서 알려 줄 것
- AVD는 `Pleos_Connect_v2.1.0`, **Cold Boot**로 시작합니다.
- 콘솔은 `adb forward tcp:8088 tcp:8088` 후 사용. 주행거리는 줄일 수 없고, 비행기 모드를 켜면 콘솔이 먹통이 됩니다.
- E2E를 돌린 뒤에는 주행거리가 누적되어 있으니 인수 기준은 스크립트가 현재 값으로 잡습니다.
- 에뮬레이터를 오래 띄우는 명령(`emulator …`)은 백그라운드로 실행하고 `adb wait-for-device`와 `getprop sys.boot_completed`로 부팅을 기다립니다.
- 터미널 환경에 `adb`가 PATH에 없을 수 있으니 `ADB` 환경변수를 지정하세요.

## 커밋과 PR을 맡길 때
- `docs/개발_가이드.md`의 커밋 컨벤션과 논리 단위 분리를 지키게 합니다. ("한 번에 전부 커밋" 금지)
- 푸시·PR 생성·브랜치 보호 변경 같은 **되돌리기 어렵거나 외부에 보이는 작업은 사람이 확인한 뒤** 실행하게 합니다.
- AI가 작성한 코드도 사람이 리뷰합니다. PR 설명에 어떤 도구를 썼는지 적어 두면 리뷰가 쉬워집니다.
- 커밋 트레일러 규칙은 각 도구의 설정을 따릅니다(Claude Code는 `Co-Authored-By` 자동 추가).

## 프롬프트 예시
```
docs/인수인계.md를 읽고 F-05 정차 후 대응 화면에 "정비소 안내" 버튼 문구를 바꿔 줘.
AppViewModelFlowTest에서 영향받는 테스트를 먼저 찾아서 알려 주고,
수정 후 ./gradlew testDebugUnitTest 결과를 보여 줘. 커밋은 하지 마.
```
